# North Star

> Replace this file with your project's north star after instantiation.
>
> A north star document answers: what does "done" look like for this product?
> Not done for a sprint — done in the sense that the product has succeeded.
> Write it as a set of observable conditions, not aspirations.
>
> Example structure (from diane-v01):
> - 5 north-star questions the product must answer
> - The worst-case scenario the product must serve
> - What "working" looks like to a real user on a real bad day
>
> Keep it short (one page). The constitution governs process; the north star governs purpose.
